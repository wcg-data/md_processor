## Bug 根因分析

### Bug 位置
`src/common_utils.rs:201-243` - `fill_missing_minutes()` 函数

### Bug 描述
跨日时段（如 21:00-02:30）判断错误：
- 当 date=2024-09-10 有 21:17 的bar时（实际是前一天夜盘的后半段）
- `fill_missing_minutes` 误判为"2024-09-10 有夜盘数据"
- 错误补全了 2024-09-10 21:00-23:59 的 180 个 volume=0 bar

### 实际数据情况（au2409）
```
date=2024-09-10: 279 条tick
  trade_time范围: 2024-09-09 21:17:48 ~ 2024-09-10 20:59:00.500000
  → 有 2024-09-09 的夜盘数据，但没有 2024-09-10 的夜盘数据

date=2024-09-11: 2 条tick  
  trade_time范围: 2024-09-11 15:00:00.500000 ~ 2024-09-11 20:59:00.500000
  → 只有日盘数据，没有任何夜盘
```

### 正确行为（on_tick）
- 数据驱动，只有tick才生成bar
- 2024-09-10 没有 21:00-23:59 的夜盘tick → 不生成bar ✅

### 错误行为（on_batch）
- `fill_missing_minutes` 看到 date=2024-09-10 有 21:17 的tick
- 误判为"2024-09-10 有夜盘数据"
- 补全了 2024-09-10 21:00-23:59（180分钟）❌

## 修复建议

需要在 `fill_missing_minutes` 中区分跨日时段的前半段和后半段：
- **前半段**（如 21:00-23:59）：属于当天夜盘的开始
- **后半段**（如 00:00-02:30）：属于前一天夜盘的结束

当 date=X 的 bar 在 21:00-23:59 时，应该判断为"date=X 的夜盘有数据"。
当 date=X 的 bar 在 00:00-02:30 时，应该判断为"date=X-1 的夜盘有数据"。
